# ROS 2 Humble Devcontainer — Quickstart

Works the same way on Linux, Windows (WSL2), and macOS.

## 1. Prerequisites (all platforms)
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Windows/macOS, WSL2 backend — not Hyper-V) or Docker Engine (Linux)
- [VS Code](https://code.visualstudio.com/) + the "Dev Containers" extension
- **Windows only:** open the project through WSL2 — either launch VS Code
  with `code .` from a WSL2 terminal inside the project folder, or use
  "Dev Containers: Reopen in WSL" first. This is what lets the automatic
  setup step (below) detect your GPU correctly.

## 2. Open the project
1. Put the contents of `.devcontainer/` at the root of your workspace.
2. Open the folder in VS Code.
3. Command Palette → **Dev Containers: Reopen in Container**.

That's it — `initializeCommand` runs `setup.sh` automatically before the
build, detecting your OS and GPU and picking the fastest working setup:

| Your machine | What you get, automatically |
|---|---|
| Linux, GPU present | Native X11 window, GPU-accelerated |
| Windows 11 (WSL2 + WSLg), GPU present | Native window via WSLg, GPU-accelerated |
| Windows 10 (WSL2, no WSLg) or GPU not detected | Browser GUI (noVNC), software-rendered |
| macOS | Browser GUI (noVNC), software-rendered (no GPU passthrough exists on Mac) |
| No GPU anywhere | Browser GUI (noVNC), software-rendered |

If you're on a browser-GUI (noVNC) profile, open `http://localhost:6080/vnc.html`
to see Gazebo/RViz2. On a native-display profile, GUI windows just appear
on your desktop like any other app.

## 3. Forcing a specific setup
```bash
cd .devcontainer
./setup.sh --accel=software   # force software rendering even with a GPU
./setup.sh --gui=false        # headless — no GUI stack at all (CLI-only work)
./setup.sh                    # back to auto-detect
```
Then **Rebuild Container**.

## 4. Using it without VS Code
```bash
cd .devcontainer
./setup.sh
docker compose up -d
docker compose exec ros2 bash
```

## Notes
- `docker-compose.override.yml` is regenerated by `setup.sh` — don't hand-edit it, your changes will be overwritten on next rebuild.
- The checked-in version of `docker-compose.override.yml` is a no-op (software + noVNC), so a fresh clone works even before anyone runs `setup.sh`.
- If GUI stack ever needs a manual restart (noVNC profiles only):
  ```bash
  sudo supervisorctl -c /etc/supervisor/supervisord.conf restart all
  ```
